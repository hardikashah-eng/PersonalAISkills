# Finding the moment in the user's connectors

Goal: find **one** specific moment where the recipient made a tangible difference
for the user — with the least reading possible. Read-only, always.

## 0. See what's connected

Check the connectors available in the session (email, chat, LinkedIn, calendar,
docs). Use only what's there. If nothing personal is connected, fall back to the
three interview questions in SKILL.md and mention once which connector would help
next time (e.g. "With Gmail connected I could find this for you").

Never ask the user for passwords, never use a browser to log into their accounts
for this skill, and never widen the search beyond the recipient.

## 1. Resolve the recipient

Find the recipient's identity in each source: display name, email address,
Slack/Teams/Lark handle, LinkedIn connection. Use it only for searching — the
handle and address never appear in the note. If several people match the name,
ask the user which one (show role or company, not contact details).

## 2. Search, narrow to wide

Run searches scoped to the recipient first, then add signals. Stop as soon as you
have 2–3 strong candidates.

| Source | Query ideas |
|---|---|
| Email (Gmail / Outlook) | `from:<them>` or `to:<them>` + `thank`, `thanks so much`, `grateful`, `appreciate`, `couldn't have`, `saved me`, `worked!`, `got the offer`, `intro`, `introducing`, `recommend`, `reference`, `feedback`, `review` |
| Slack / Teams / Lark | DMs with them; channel messages mentioning them + `thank`, `🙏`, `kudos`, `shoutout`, `unblocked`, `covered`, `pairing`, `helped` |
| LinkedIn | Recommendations they wrote for the user, endorsements, messages around job changes, intro messages |
| Calendar | Recurring 1:1s or mentoring sessions with them (shows sustained help — count and span, not content) |
| Docs | Docs they commented on heavily or co-authored with the user (reviews, mentorship plans) |
| WhatsApp *(opt-in)* | The 1:1 chat with them only (never groups unless the user points to one): `thank`, `🙏`, `❤️`, `shukriya`, `gracias`, `couldn't have`, voice-note captions/transcripts if available |
| SMS / iMessage *(opt-in)* | The thread with them only: same gratitude and outcome signals |

### WhatsApp and SMS — explicit opt-in

These are the most private channels people have, often holding family and
health conversations. Before reading them:

1. Ask: "Can I look at your WhatsApp/SMS thread with <first name> to find a
   moment to thank them for? I'll only read that one conversation and won't save anything."
2. Proceed only on a clear yes, for that recipient and this note. Don't carry the
   permission over to other recipients or later notes.
3. Read only the 1:1 thread with the recipient; stop once you have candidates.
4. If no WhatsApp/SMS connector exists, the user can paste or export the relevant
   few messages instead — never ask for a full chat export.

Messaging threads also reveal **relationship cues** (how they address each other,
language mix, emoji and humour style) and **possible triggers** (a recent loss,
illness, a hard time). Use these only to set tone and steer around pain
(`relationships-and-culture.md`); never surface them in the summary or the note.

Gratitude the **user** already expressed is the strongest signal — the user's own
"thank you, this changed everything" points straight at the moment.

## 3. Score candidates

Score each candidate 0–2 on each dimension; keep the top 2–3.

| Dimension | 0 | 1 | 2 |
|---|---|---|---|
| Specificity | vague ("thanks for the help") | an identifiable task | a concrete act with a when |
| Tangible outcome | none visible | likely outcome | outcome confirmed (shipped, hired, solved, learned, "it worked") |
| Effort / generosity | routine part of their job | went a bit beyond | clearly beyond (their own time, weekend, risk, advocacy) |
| Emotional weight | neutral | user relieved/pleased | user said it mattered a lot |
| Safety | needs heavy abstraction (health, money, private conflict) | small abstraction | safe as-is |

Prefer moments with a clear **before → help → after** arc. Tie-breakers: the
user's own words of thanks; more recent; something the recipient may not know
mattered so much (the note can tell them).

## 4. Summarise for the user — safely

Present each candidate as one line: approximate date, what they did, what changed.
Already abstracted per `safety.md`; no message quotes, no third-party names unless
needed, no contact details. Let the user pick, merge, or correct. Use only what
they confirm.

## 5. Minimise retention

Keep only the confirmed one-line summary in working notes. Do not save message
contents, addresses, or handles to files, memory, or the note.
